# Kaggle 竞赛调度层

**这个 skill 不替代其他 skill。** 它只回答三个问题：**先做什么、怎么判断改动是真是假、什么时候停。** 具体动作交给：

| 做什么 | 交给 |
|---|---|
| 拉数据、核对文件 | `kaggle-data` |
| 数据画像 | `kaggle-eda` |
| 切分与泄漏检查 | `kaggle-validation` |
| 建模、特征、调参、集成 | `kaggle-modeling` |
| 生成并校验 submission | `kaggle-submission` |

本 skill 的定位是**提问清单 + 判定标尺**，不是答案库。下面每一条都可以被证据推翻——见最后一节「反教条条款」。

---

## 0. 开赛前必答（写进 `reports/plan.md`）

先回答，再动手。这五个答案决定后面每一步怎么走。

1. **数据形态**是什么？（行独立表格 / 分组 / 时间序列 / 文本 / 图像 / 多模态）
2. **官方指标**是什么？（AUC / LogLoss / RMSE / RMSLE / F1 / MAP@k / QWK）
3. **test 与 train 的关系**？（随机同分布 / 按组 / 按时间）
4. **提交配额**多少？（决定能不能用一次提交去校准 CV）
5. **结算时间与奖牌规则**？（Playground / Getting Started / Community 系列 `awards_points=False`，没有奖牌）

然后强制写一行：

```
和上一个比赛的关键差异：
```

**作用**：框架的价值是省下重复劳动，把注意力留给新问题。如果它让你看不见新问题，就该改了。

## 1. 数据形态路由

先分流，再进流程。**不同形态的验证方案完全不同，这里错了后面全错。**

| 数据形态 | CV 怎么切 | 第一个 baseline | 注意事项 |
|---|---|---|---|
| 行独立表格 | `StratifiedKFold` / `KFold`，5 折 | LightGBM / HistGradientBoosting | 最常见，本 skill 默认路径 |
| 同一实体多行 | `GroupKFold` / `StratifiedGroupKFold` | LightGBM | 组不能跨折，否则 CV 虚高 |
| 时间序列 | `TimeSeriesSplit` 或按时间切 | naive（上一期 / 移动平均） | 特征只能用过去信息 |
| 文本 | `StratifiedKFold` | TF-IDF + 线性模型 | 特征工程是决定性的，不是可选项 |
| 图像 | 按来源 / 病人 / 采集批次分组 | 预训练骨干（timm）微调 | 同源图像跨折会泄漏 |
| 极不平衡（<1%） | `StratifiedKFold` | LightGBM | 指标常是 PR-AUC / F1，不是 accuracy |

## 2. 阶段阶梯

每阶段格式：**要回答的问题 → 通过标准 → 不通过怎么办**。
产出必须是**一句带证据的判定**，不是打个勾。写不出这句判定，说明这阶段白做了。

### S1 数据完整
**问题**：文件齐不齐、行数对不对？
**通过**：本地文件与 `competitions files` 一一对应；行数写进 `data_manifest.md`。
**不通过**：删掉重下。**残缺文件不会报错，只会在几小时后表现为"分数莫名其妙"。**

### S2 数据画像 = 假设检验
**问题**：建模的隐含假设成不成立？
**通过**：下面每一条都有答案。

| 隐含假设 | 检验 | 不成立时 |
|---|---|---|
| train/test 同分布 | 逐列 SMD、类别 TV 距离 | SMD > 0.1 → 查漂移 / 做 adversarial validation |
| 行独立 | 查完全重复行、查分组结构 | 改用 GroupKFold |
| 无时间结构 | 按 ID / 时间分段看正类率 | 改用时间切分 |
| ID 不携带信息 | ID 与目标的关系 | 考虑把 ID 当特征或做分组 |
| 信号在哪 | 单特征 AUC / 相关系数 | 全 ≤0.5 → 先怀疑数据或标签 |

### S3 验证方案
**问题**：CV 能不能代表线上？
**通过**：切分方式与 test 的生成方式一致；指标用官方公式在**完整 OOF** 上算一次（不是各折平均）；折索引落盘、全程复用。

### S4 基线
**问题**：地板分是多少？
**通过**：跑通、拿到 OOF AUC、记录折间 std、OOF 落盘。

### S5 CV—LB 校准
**问题**：CV 值不值得信？
**通过**：**|CV − LB| < 0.001**（首次提交）。
**不通过**：先查泄漏和漂移，**不要**继续优化——CV 不可信时后面每个结论都是幻觉。
**注意**：public LB 是 test 子集，抽样噪声可达 ±0.0005，所以 CV–LB 偏移量本身会变，不能当精确预测。

### S6 噪声标尺 ← 最容易跳过、也最关键
**问题**：多小的改进是噪声？
**动作**：同一配置、只换种子（折种子 + 模型种子），重跑 2 次，记录 OOF 差异。
**通过**：得到一个**你自己数据上的**数字。

> ⚠️ **不要照抄别人的阈值。** s6e11 的标尺是 0.00014–0.00016，因为它是 70 万行 + AUC。换数据量、换指标，标尺就变。小数据集可能大一个数量级；RMSE 和 AUC 的标尺不可比。

由此建立你自己的判定表：

| Δ 相对噪声 | 判定 |
|---|---|
| < 2 倍噪声 | 噪声，不下结论 |
| 2–6 倍 | 需要第二个种子确认 |
| > 6 倍 | 可直接采信 |

### S7 瓶颈诊断（互斥假设）
**问题**：该往哪个方向使劲？模型是欠拟合还是过拟合？
**动作**：设计 3 组**互斥**假设，不要盲扫网格。

| 组 | 方向 | 回答 |
|---|---|---|
| A 容量+ | `lr↓`、`num_leaves↑`、`min_child_samples↓` | 是否欠拟合 |
| B 正则+ | `num_leaves↓`、`min_child_samples↑`、`reg_lambda↑`、`colsample↓` | 是否过拟合 |
| C 加权/重采样 | `scale_pos_weight` / SMOTE | 不平衡是否值得处理 |

**通过**：三组各有明确结论，方向确定。
**收敛判断**：看边际收益。基线 → B_reg(+0.00094) → B_plus(+0.00021)，**收益掉到 1/4 就停**。

> **顺序说明**：`kaggle-modeling` 写的顺序是「特征工程 → 调参」。本 skill 建议**先跑参数诊断再决定要不要做特征**——参数实验通常更快，且能判断瓶颈方向（是容量问题还是信息问题）。
> **例外**：文本、时序聚合、多表 join 这类比赛，特征的边际价值远大于调参，可以反过来。

### S8 特征工程（分批）
**问题**：有没有模型没拿到的**新信息**？
**动作**：按类别分批，**每批 3–5 个，单独加入、单独评估**。一次加 13 个，涨了不知道是谁的功劳。
**通过**：每批一个明确的 Δ（对照 S6 的标尺）+ 判定。
**不通过**：记下否定结论，回到 S9 换方向（减特征 / 换模型 / 探测结构）。

### S9 特征消融
**问题**：哪些列可以删？
**动作**：留一法，每次只删一列。
**通过**：每列边际贡献 + 一个"删列后"的配置。
**注意**：单列 Δ 常落在噪声内，但**多列合起来的累积效应会显形**；累积效应也要跨种子验证。
**关键**：**单特征 AUC ≈ 0.5 不等于该列没用**——它可能只靠交互贡献。删列只能靠消融，不能靠单特征指标。

### S10 集成
**问题**：模型多样性够不够？
**动作**：训练多个"犯错方式不同"的模型 → **先算 OOF 相关性** → 再比较融合方式。
**通过**：相关性 < 0.98 才值得堆模型。
**注意**：
- 相关性 ≥ 0.98，集成收益必然很小，先测相关性再决定投入
- 优化权重形态极端（某模型 0.9+、某模型归零）→ OOF 过拟合，退回等权
- **模型多样性比模型数量重要**

### S11 停止判断
**问题**：还值不值得投入？
**三条独立证据**（任一成立可考虑停，三条都成立则果断停）：

1. 没有确定性公式可反推：用其余列预测每个数值列，R² 是否接近 1
2. 标签不是确定函数：按离散特征分组，看「**全 1 组**」的数量（**不要看「全 0 组」**——正类率低时全 0 是必然的）
3. 加容量 / 加特征 / 加模型全部无效或有害

**停止不等于失败。** 投入产出比翻转时就该停，此时该做的是把流程和否定结论整理成文档。

## 3. 时间预算不足时的快速通道

剩余时间 < 1 周，或这是练手赛：

```
S1 → S2 → S3 → S4 → S5 → S6 → 最强单模型 → 提交
```

跳过 S7–S10 的全部精细化。**但 S5 和 S6 不能跳**——它们决定你后面所有判断是否可信，成本只有几十分钟。

## 4. 适用边界

下面这些结论**来自 playground-series-s6e11（表格 + AUC + 1.67% 正类 + 70 万行 + 同分布），只在条件成立时有效**。条件变了就要重测，不能当规则用。

| 结论 | 成立条件 | 条件失效时 |
|---|---|---|
| 类加权 / 重采样有害 | 指标是 **AUC**（只看排序） | LogLoss / F1 / 召回导向 → 必须重测，往往有用 |
| 树模型不需要标准化 / log1p / 分箱 | 模型是**树模型** | 线性模型、神经网络、KNN → 必须要 |
| 人工特征工程无效 | 信号是**加性**的、GBDT、大样本 | 文本 / 时序聚合 / 多表 join → 特征是主要来源 |
| 集成收益小（+0.0002） | 模型间相关性 **≥ 0.98** | 小数据集、异构模型族 → 收益可大得多 |
| `StratifiedKFold` | 行**独立同分布**、无时间结构 | 分组 / 时序 → 换 `GroupKFold` / `TimeSeriesSplit` |
| 16 列特征最优 | **仅此数据集** | 任何新比赛 → 从原始列重新做消融 |
| 噪声标尺 ≈ 0.00015 | 70 万行 + AUC | 任何变化 → 重测（见 S6） |

**一句话**：左边是「怎么想」，右边是「上次的答案」。**只搬左边。**

---

## 5. 反教条条款

这个 skill 本身也可能错。出现下面情况时，**先改流程，再开跑**：

1. **S2 发现有任一前提与 s6e11 不同**（分组、时序、文本、小样本、指标不是 AUC）→ 先按第 4 节改流程，不要直接往下走。
2. **某阶段的通过标准明显不适用**→ 在 `reports/plan.md` 写明理由后跳过，不要为了"走完流程"硬走。
3. **某个改动违反了本 skill 的建议，但你有具体的机制解释**→ 做，然后记录结果。机制解释比清单更可靠。
4. **所有阶段都走完了但分数还在涨**→ 说明流程有遗漏，回头找哪一步的判断太保守。

## 6. 产出

```
reports/
├── plan.md            开赛前的五问 +「和上次的差异」
├── data_manifest.md   数据清单
├── eda_report.md      EDA 结论（假设是否成立）
├── cv_log.md          实验表：改动 / OOF / 折间 std / **判定**
├── submissions.md     提交表：文件 / CV / LB / 差值 / 结论
├── noise_floor.json   噪声标尺实测结果
└── final_summary.md   复盘（含否定结论）
```

`cv_log.md` 一行一次实验，**必须包含「判定」列**——记录结论，而不只是数字。
